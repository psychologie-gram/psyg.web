# Agent instructions

## Project overview

- This is an Astro 7 website using Tailwind CSS 4, DaisyUI, and local-first
  Tina CMS.
- Use Node.js `>=22.12.0` and npm. The repository contains a checked-in
  `package-lock.json`.
- Editorial content lives in `src/data/*.json` and is modeled in
  `tina/config.ts`.

## Local development

- Run `npm install` once, then use `npm run dev` for local development.
- `npm run dev` starts both Tina and Astro. Astro serves the website and
  `/admin/` on port `4321`; Tina serves the local GraphQL API and admin assets
  on port `4001`.
- Do not use `astro dev` directly when testing or editing through the admin.
  It does not start Tina's local server. The VS Code launch configuration must
  use `npm run dev` as well.
- The local editing setup does not require TinaCloud credentials.

## Tina CMS rules

- Keep Tina as the only CMS. Do not add another CMS's dependencies, config
  files, or replacement admin routes.
- `public/admin/` is generated by Tina and is ignored by git. Never manually
  edit or commit its contents.
- Keep Tina schema changes in `tina/config.ts`, data normalization in
  `src/lib/tina/data.ts`, and editable-region wiring in
  `src/components/tina/` and `src/lib/tina/`.
- Prefer the existing semantic component and UI-wrapper patterns over exposing
  arbitrary CSS classes or markup through CMS fields.

## Validation

Run the smallest applicable existing checks after changes:

```sh
npm run astro -- check
npm run build
```

For admin-related changes, also start `npm run dev` and confirm that
`http://localhost:4321/admin/` loads and that the local GraphQL server is
available. Do not add a new test or build tool just for this smoke check.
